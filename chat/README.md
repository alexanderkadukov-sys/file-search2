# OpenChat — веб-чат без регистрации

Публичный адаптивный чат: сообщения, фотографии, PDF и TXT, три комнаты, просмотр вложений, поиск по текущей истории и мобильный интерфейс. Email и телефон посетителю не нужны: он вводит только псевдоним.

## Запуск настоящего чата

1. Создайте проект на https://supabase.com/dashboard.
2. В разделе Authentication включите Anonymous Sign-ins. Перед массовым запуском настройте CAPTCHA/Turnstile.
3. Откройте SQL Editor → New query; вставьте и выполните весь файл schema.sql. Он создаст базу, RLS-политики, публичное файловое хранилище и Realtime.
4. Найдите Project URL и Publishable key (или legacy anon key). Запишите эти два значения в config.js. Не используйте service_role или secret key — их нельзя публиковать!
5. Откройте чат на двух устройствах, выберите разные имена и проверьте доставку текста и фото в реальном времени.

После настройки GitHub Pages отдаёт фронтенд, а Supabase хранит и доставляет сообщения и файлы. Если Supabase не настроен, сайт намеренно показывает демо-режим: сообщения видны только в текущем браузере.

## Размещение на GitHub Pages

Исходники рассчитаны на статический хостинг (без сборки npm). Можно опубликовать корень в отдельном репозитории или папку chat/ внутри существующего GitHub Pages. Если основная страница репозитория уже работает, добавление каталога chat/ её не заменяет.

## Функции

- Общий чат, Фото, Файлы.
- Анонимный вход без ручной регистрации и переписка в реальном времени.
- JPG, PNG, WEBP, GIF, PDF, TXT; ограничение файла 8 МБ.
- Мобильный интерфейс, эмодзи, просмотр изображений, копирование текста.
- Supabase Realtime и Presence, история до 70 сообщений на комнату.

## Ограничения и предупреждения

Это открытый публичный чат, не защищённый приватный мессенджер: нет сквозного шифрования, приватных сообщений и подтверждённых личностей. Любой пользователь может выбрать чужое имя. Не публикуйте пароли, документы и персональные данные.

SQL использует RLS, запрещает подмену sender_id и ограничивает частоту сообщений до 12 за минуту на анонимного пользователя. Это не блокирует создание множества анонимных аккаунтов и массовую загрузку файлов. Перед настоящим публичным запуском обязательно внедрить CAPTCHA, модерацию, жалобы, ограничения хранилища/затрат и правила удаления контента.

## Контрольный тест

1. Откройте сайт на телефоне и ПК.
2. Отправьте сообщение с ПК; на телефоне оно должно появиться без перезагрузки.
3. Отправьте JPG и TXT/PDF.
4. Попробуйте загрузить файл более 8 МБ и EXE: отправка должна блокироваться.
5. Проверьте отсутствие secret keys в репозитории.

Код: index.html, style.css, app.js, config.js, schema.sql. Работа в браузере, без сборки.
